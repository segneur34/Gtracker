## Les trois risques (gardes du 187, à garder vertes **telles quelles**)

1. Migrations d'activités (`ACTIVITIES_VERSION`, graines terre) et `PRESET_RESETS` (v2 bases terre, v3 Marche, v4 `jumps.kite`) : un réglage de voile déjà migré ne doit jamais être effacé une seconde fois. Les migrations terre deviennent des no-op **nommés** (la version ne recule pas, aucune nouvelle reprise). Garde : `hooks/useSportSettings.guard.test.ts` (réglages 0.4.61).
2. `SUMMARY_CALC_VERSION` : inchangé pour un champ retiré ; le profil d'une session sans calcul (`UNCLASSIFIED_PROFILE`) donne le même résumé. Garde : `library/summaryFrozen.test.ts`.
3. Lecteurs à type fermé (`hiddenFamilies`, `moduleActivity`, `tabs`, chiffres du direct, champs par activité) : une famille ou un calcul disparu est **ignoré**, jamais l'objet rejeté. Garde : `library/settingsImport.guard.test.ts`. Les fiches d'un dossier mémoire de Tracker complet (course, vélo, fractionné) restent lisibles, listées sans analyse ou masquées (le 306 tranchera le détail) ; aucune fiche n'est réécrite ni perdue.
