# Lots en parallèle (lu par `/chaine` quand Ensuite a 2 ou 3 lots prêts)

Pour aller plus vite : dès que Ensuite a 2 ou 3 lots prêts, leurs agents `lot` codent en même temps, sans attendre que l'utilisateur le demande, si toutes ces conditions sont vérifiées avant le lancement.
- Indépendants : aucun ne dépend d'un autre (« dépend de »), et les fichiers que leurs briefs disent toucher ne se recouvrent pas. Chaque agent reçoit la liste des fichiers des autres, à ne pas toucher ; s'il le doit, il le dit dans son rapport au lieu de le faire.
- Isolés : le premier lot dans le dépôt principal, chacun des autres dans son worktree (`isolation: "worktree"` de l'appel, sous `.claude/worktrees/`, que git, vitest et oxlint ignorent). Pas de lien `node_modules` à poser (refusé aux agents, et inutile : Node remonte à celui du dépôt) ; l'agent n'y lance ni banc ni build.
- À jour : l'isolation part de ce qui est envoyé sur GitHub (`origin/main`), pas du dernier commit local (vu le 04/11 : deux worktrees sans les deux lots commités avant leur lancement). S'il y a des commits non envoyés, la première consigne de l'agent est `git merge --ff-only <dernier commit>` dans son worktree, avant toute modification (la pile de `git stash` est partagée entre worktrees : pas de stash), et le brief se lit par chemin absolu dans le dépôt principal tant qu'il n'y est pas commité.
- Sans écriture hors de lui : un agent en worktree ne peut pas éditer le dépôt principal. Une correction après rapatriement passe par un correctif qu'il rend (`git apply` par l'orchestrateur) ou par un agent neuf.
- Jamais en parallèle : un lot dont la fiche dit « seul dans sa session » (noyau voile), et un lot qui attend une maquette, une réponse ou la lecture de son plan. Le domaine ne compte pas : deux lots d'enregistrement, de fiches ou de mémoire se codent en même temps dès que leurs fichiers ne se recouvrent pas (décision de l'utilisateur du 31/10 : le parallèle est la règle, l'attente l'exception). Un plan ou une réponse en attente ne retient que son lot : les autres partent.
- Rapatriés un à un : une fois le lot précédent commité, le travail d'un worktree est rapporté dans le dépôt principal (`git -C <worktree> add -A`, node_modules étant ignoré, puis `git -C <worktree> diff --cached --binary HEAD | git apply --3way`, puis `git reset -q` pour ne rien laisser préparé), puis passe l'étape 4 en entier, comme s'il avait été fait là, sur l'arbre qui porte déjà les lots précédents. Un conflit à ce moment est un ÉCHEC de ce lot (étape 6) ; les autres continuent.
- Nettoyés : après le commit, s'il reste un lien `<worktree>/node_modules` d'une ancienne session, le retirer seul par `rm <worktree>/node_modules` (sans `-r` : jamais d'effacement récursif à travers un lien, qui viderait le vrai `node_modules`) ; puis `git worktree remove --force <worktree>`, `git branch -D` de sa branche, et `rmdir` du dossier s'il reste vide.
- Rendu le plus tôt possible : un lot fini avant celui qui le précède dans l'ordre peut être rapatrié et commité le premier, puisqu'il est indépendant.
